# Маршрутизация: что идёт через VPN, что напрямую, что не открывается

Окно «Маршрутизация» (чип под кнопкой питания на главном экране; в настройках его нет) устроено так же, как в SenAWG для
Android: два списка «Через VPN» и «В обход VPN», «Всё остальное» и продвинутые правила по порядку — как «простые» и
«продвинутые» правила [Throne](https://github.com/throneproj/Throne), строки `префикс:значение`. Свой механизм Throne (sing-box внутри TUN) у нас не
нужен: решение принимает служба SenAWG через собственный DNS-прокси и таблицу маршрутов, поэтому часть возможностей
Throne переносится целиком, а часть нет (таблица ниже).

## Что перенесено из Throne, а что нет

| Возможность Throne | У нас | Почему |
|---|---|---|
| Три списка Proxy / Direct / Block, действие по умолчанию (Basic) | есть: вкладки «Через VPN» и «В обход VPN»; «Блокировать» — правилом в «Продвинутых» | основа |
| Правила по порядку (Advanced) | есть: «Продвинутые», только строки `префикс:значение` | остальные атрибуты правил Throne (порты, протокол и др.) ниже |
| Простой режим «только сайты» | был; сохранённый открывается списками | |
| `domain:`, `suffix:`, `keyword:`, `regex:` | есть | решается при запросе адреса у DNS |
| `ip:` (адрес или сеть) | есть | статические маршруты |
| `processName:`, `processPath:` (правила по программам) | **только Linux** (cgroup v2 + nftables); в macOS и Windows не будет | таблица маршрутов не знает, какая программа открыла соединение; в Linux это знает ядро |
| `ruleset:` (geoip / geosite) | планируется | нужны скачиваемые списки и быстрая укладка тысяч сетей |
| Профили, импорт `throne://route/…`, обновление по ссылке | планируется | |
| Порты, протокол (tcp/udp), сеть, Wi-Fi, inbound, sniff, resolve, hijack-dns, Warp-bypass | нет | это решения по каждому соединению внутри sing-box; наша служба решает по адресу |

## Окно: два списка и «Продвинутые»

Так же, как на Android, только на компьютере всё можно менять и при включённом VPN — применится при следующем подключении.

Первая страница — две вкладки, у каждой свой список, оба действуют сразу:

- **«Через VPN»** — сайты и сети, которые идут через туннель;
- **«В обход VPN»** — те, что идут напрямую.

В поле по одному в строке; строка без префикса — сайт с поддоменами (`suffix:`), можно и с префиксом. На вкладке — сколько
в списке правил. В Linux под сайтами ещё список **«Программы»**: имя исполняемого файла, по одному (это строки
`processName:` того же списка). В macOS и Windows его нет: правила по программам там не работают.
Если в «Блокировать» есть строки (их начинают только правила), этот список показан под вкладками.
Ниже — **«Всё остальное»**: «Через VPN» или «Напрямую».

Кнопка **«Продвинутые»** внизу открывает правила по порядку (вкладка Advanced в Throne): переключатель «Использовать
продвинутые правила», «Всё остальное», название набора и любое число правил — у каждого название, действие (через VPN,
напрямую, блокировать), свои строки, выключатель, кнопки «выше» / «ниже» и удаление. Побеждает первое совпавшее правило
сверху. До 100 правил. Пока переключатель выключен, правила затемнены и не меняются; пока включён — затемнены списки, и над
ними сказано, что сейчас действуют правила. Первый раз правила начинаются с трёх списков («Через VPN», «Напрямую»,
«Блокировать») с теми же строками, так что ничего не нужно вписывать заново. Переключение хранит обе части.

Сохранённый раньше «Простой» режим (только сайты: «кроме этих», «только эти», «блокировать эти») действует как прежде и
показывается списками, в которые он превращается; при первой правке он ими и становится. Прежние «Продвинутый → Списки» и
«По порядку» — это теперь вкладки и «Продвинутые».

Общее для всех режимов:

- Список сохраняется, только пока все строки разобраны; ошибка показана под списком с номером строки.
- Пока правил нет (или остались только те, что здесь не применяются), всё идёт через VPN, а чип пишет «Всё через VPN».
- Чип на главном экране показывает, что в силе: «Кроме 3 сайтов», «Только 2 сайта», «Блок 5 сайтов» или «Название · 4 правила».
- Правила применяются **при следующем подключении**. Если вы изменили их при включённом VPN, сверху появится
  «Правила маршрутизации изменены. Они применятся при переподключении» с кнопкой «Переподключиться».
- «Как писать правила» в «Продвинутых» открывает краткую справку с теми же примерами, что ниже.

## Синтаксис строк

| Префикс | Значение | Пример |
|---|---|---|
| `domain:` | ровно это имя, без поддоменов | `domain:nura.eco` |
| `suffix:` | имя и все его поддомены | `suffix:ozon.ru` |
| `keyword:` | часть имени (2–63 символа: a–z, 0–9, `.`, `-`, `_`) | `keyword:adservice` |
| `regex:` | регулярное выражение (RE2: без просмотра вперёд/назад и обратных ссылок, до 256 символов) по имени в нижнем регистре | `regex:\.(ru\|su)$` |
| `ip:` | адрес или сеть в виде CIDR; IPv6 тоже; не шире /8 (IPv4) и /16 (IPv6) | `ip:10.0.0.0/8` |
| `processName:`, `processPath:` | программа по имени исполняемого файла (регистр важен) или по полному пути; **только Linux** | `processName:spotify` |
| `ruleset:` | `geoip-ru`, `geosite-ru` или ссылка `https://…`; пока не применяется | `ruleset:geoip-ru` |

- Строка без префикса — это `suffix:` (если похожа на адрес или сеть — `ip:`), так что старые списки сайтов
  работают как есть. `*.example.com` читается как `example.com`.
- Регистр префикса не важен. Пустые строки и строки с `#` в начале пропускаются.
- Имена международные записываются как есть: `пример.рф` превращается в `xn--e1afmkfd.xn--p1ai`.
- Всего не больше 2000 правил на все списки.

## Приоритет

В списках как в Throne: сначала «Через VPN», потом «В обход VPN», потом «Блокировать»; побеждает первое совпавшее правило. В «Продвинутых»
порядок ваш, сверху вниз. В «Простом» все сайты с одним действием, порядка нет. Если ничего не совпало — «Всё остальное».

- Правило по имени срабатывает, когда программа спрашивает адрес этого имени: служба кладёт маршрут на полученные
  адреса. Правило `ip:` работает маршрутом по сети. Если оба относятся к одному адресу, **побеждает правило по
  имени**: маршрут на один адрес длиннее маршрута на сеть. В sing-box порядок был бы строго по списку.
- **Блокировка** имени: служба отвечает «такого имени нет» (NXDOMAIN) на любой тип запроса, адрес не запрашивается.
  Блокировка `ip:` — маршрут в никуда (в Windows не поддерживается; блокировка по именам работает везде).
- Блокировка по имени не остановит программу, которая обращается к адресу напрямую, без DNS.

## Примеры

Все блоки `routing-lines` ниже и в этом файле проверяются тестом (`tests/routingDocs.test.ts`): каждая строка должна разбираться без ошибок. В «Простом» режиме нужны только сайты, без префиксов, поэтому примеры ниже — для «Продвинутого».

**Через VPN только нужные сайты** — «Всё остальное: напрямую», список «Через VPN»:

```routing-lines
suffix:youtube.com
suffix:googlevideo.com
suffix:ifconfig.me
```

**Всё через VPN, кроме российских сайтов** — «Всё остальное: через VPN», список «В обход VPN»:

```routing-lines
regex:\.(ru|su|xn--p1ai)$
```

**Ozon напрямую** — «Всё остальное: через VPN», список «В обход VPN». У магазина служебные домены отдельно: картинки и
скрипты лежат на `ozone.ru`, и с адреса VPN они не отдаются, поэтому нужны оба:

```routing-lines
suffix:ozon.ru
suffix:ozone.ru
```

**Блокировка рекламы** — список «Блокировать»:

```routing-lines
suffix:doubleclick.net
keyword:adservice
suffix:ads.example.com
```

**Локальные сети напрямую, одну сеть заблокировать** — «Всё остальное: через VPN»:

```routing-lines
# список «В обход VPN»
ip:192.168.0.0/16
ip:10.0.0.0/8
# список «Блокировать»
ip:203.0.113.0/24
```

**Приложения через VPN (только Linux)** — «Всё остальное: напрямую», как на скриншоте Throne:

```routing-lines
processName:spotify
processName:Telegram
domain:nura.eco
```

## Как это устроено

Служба держит свой DNS-прокси на `127.77.0.1:53` (UDP и TCP) и направляет на него системный DNS на время работы VPN.

1. Программа спрашивает адрес имени. Прокси проверяет имя по спискам: «Блокировать» отвечает NXDOMAIN, остальное
   спрашивает у DNS туннеля (если имя идёт через VPN) или у DNS системы, сохранённого до подключения (если напрямую).
2. Если путь имени не совпадает с «Всё остальное», служба кладёт маршрут на каждый адрес из ответа **до того, как
   ответ вернётся программе**: в туннель или мимо него.
3. Ответ для таких имён живёт не дольше 5 минут (TTL урезается), маршрут — час с последнего ответа, всего таких
   маршрутов не больше 8192, самые старые вытесняются. После отключения всё снимается.
4. У пира остаётся `AllowedIPs = 0.0.0.0/0, ::/0`: куда идёт трафик, решают маршруты ОС, поэтому лимита в 32
   записи `AllowedIPs` у этой схемы нет.
5. Если DNS системы не отвечает (провайдер режет UDP/53), прокси пробует тот же сервер по TCP, а при полном отказе
   спрашивает DNS туннеля: имя всё равно маршрутизируется по списку.

Подробности по системам: [Linux](linux.md#маршрутизация), [macOS](macos.md#маршрутизация),
[Windows](windows.md#маршрутизация).

## Правила по программам (только Linux)

`processName:spotify` и `processPath:/usr/bin/spotify` решают по программе, а не по адресу. Служба держит три cgroup (v2) в
`/sys/fs/cgroup/senawg/` — `proxy`, `direct`, `block` — и раз в секунду просматривает `/proc`: процессы, подходящие под правило
(имя исполняемого файла или полный путь), переносятся в cgroup своего действия, а их дочерние процессы рождаются уже в ней. Цепочка
nftables в хуке OUTPUT (таблица `inet senawg`) метит пакеты сокетов из этих cgroup: меткой 51888 для «напрямую» (она и без того обходит туннель
в `route_linux.go`), меткой 51889 для «через VPN» (правило `ip rule fwmark 51889 lookup 51888` и маршрут по умолчанию в таблице 51888) и
отвечает отказом для «блокировать». Программа, которая и так идёт по умолчанию, не трогается. При отключении процессы возвращаются в прежние cgroup,
таблица и правила удаляются; после падения службы `reconcile` переносит всё из `senawg/*` в корневую cgroup и убирает таблицу.

- Нужны cgroup v2 (единая иерархия, как в современных дистрибутивах) и nftables в ядре; без них служба сообщает об этом (`hello.perApp`), правила
  по программам не отправляются, остальные работают, в журнале строка «Правила по программам не применены».
- Имя — это имя исполняемого файла (`/proc/<pid>/exe`), как в sing-box; у интерпретируемых программ (скрипты) это имя интерпретатора. Flatpak и Snap видны
  под именем своего исполняемого файла.
- **Окно до секунды**: только что запущенная программа ходит по умолчанию, пока сканер её не заметил. **Уже открытые соединения** сохраняют прежний путь.
- DNS программ не перехватывается: запросы идут в систему как обычно. Если в правилах нет ни одного правила по именам, а «Всё остальное: напрямую»,
  системный DNS не меняется.
- systemd может считать перенесённый процесс «чужим» в своём юните; при перезапуске юнита процесс вернётся в его cgroup, а сканер перенесёт его снова.

## Ограничения

- **Программы со своим DNS** (DNS поверх HTTPS в браузере, «Безопасный DNS») минуют прокси, правила по именам не
  сработают. Прокси отвечает NXDOMAIN на канарейку Firefox `use-application-dns.net` и на `mask.icloud.com`,
  `mask-h2.icloud.com` (iCloud Private Relay), чтобы они сами отступили.
- **Программы с вшитыми адресами** (без DNS) идут по «Всё остальное», пока адрес не совпал с правилом `ip:`.
- **Общий адрес у разных сайтов** (CDN): если у сайта из списка и у сайта вне списка один адрес, маршрут получат оба.
- **Служебные домены**: у сайта картинки и скрипты часто лежат на других доменах; если сайт открывается не
  полностью, добавьте и их (у Ozon это `ozone.ru`). Увидеть их можно во вкладке «Сеть» инструментов разработчика.
- **Windows**: в режиме с правилами блокировка трафика вне VPN (kill switch, WFP) не действует.
- **Уже открытые соединения** сохраняют прежний путь, пока программа не откроет новые.

## Прежние настройки

В 0.8.1–0.8.3 было «Что идёт через VPN» (режимы «кроме списка» и «только список»). При первом запуске после
обновления они переносятся в «Простой» режим: «только список» — «Через VPN только эти сайты», «кроме списка» —
«Всё через VPN, кроме этих сайтов», с теми же сайтами. Служба по-прежнему понимает запрос прежней версии приложения.

## Если что-то не так

Журнал («Диагностика») пишет строки, начинающиеся с «маршрутизация». Самые частые:

| Строка | Что значит |
|---|---|
| `Маршрутизация: по умолчанию … правил: …` | правила приняты службой и применены |
| `Маршрутизация: правила ничего не меняют…` | все правила ведут туда же, куда «Всё остальное» (обычно: сайты в «Через VPN», а «Всё остальное: Через VPN»). Чтобы через VPN шли только они, поставьте «Всё остальное: Напрямую». Чип на главном экране в этом случае пишет «Всё через VPN» |
| `Служба SenAWG старой версии не умеет маршрутизацию…` | служба не обновилась; обновите SenAWG, пока всё идёт через VPN |
| `DNS …: i/o timeout — спрашиваю DNS туннеля` | DNS системы не отвечает; имя разрешено через туннель, маршрут по списку остался |
| `DNS …: dial udp …: connect: network is unreachable` | сокет не нашёл маршрута до DNS; сообщите разработчикам, приложив журнал |
| `маршрут для … : нет основного шлюза` | нет физической сети (или шлюз не определился): маршрут «напрямую» не положен |
| `правило ip:…: …` | сеть из правила `ip:` не удалось уложить; остальные правила работают |
