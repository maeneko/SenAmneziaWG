# AmnesiaWG для Windows

Приложение остаётся обычным (без прав администратора). Всё привилегированное делает служба Windows,
которую установщик регистрирует один раз: UAC спрашивается только при установке. Работает служба только
вместе с приложением: оно её запускает, и она останавливается сама, как только приложения не стало.

```
AmnesiaWG.exe (обычные права)
   │  \\.\pipe\ProtectedPrefix\Administrators\AmnesiaWG\helper
   │                                     создать может только администратор/SYSTEM; писать — вошедшие пользователи
   ▼
awg-helper.exe service               служба AmnesiaWGHelper (LocalSystem, запуск по требованию)
   │  пишет  C:\ProgramData\AmnesiaWG\data\tunnels\AmnesiaWG.conf   (только SYSTEM и администраторы)
   │  создаёт и запускает службу  AmneziaWGTunnel$AmnesiaWG
   ▼
awg-helper.exe tunnel <conf>         пакет tunnel из amnezia-vpn/amneziawg-windows
   ├─ адаптер Wintun, адреса, маршруты, DNS, перепривязка при смене сети
   ├─ WFP: при полном туннеле (0.0.0.0/0) блокирует DNS и весь трафик вне туннеля
   └─ UAPI-пайп только для SYSTEM/администраторов → статистику отдаёт служба
```

## Службы живут ровно столько, сколько приложение

Обе службы — службы Windows: у них нет родительского процесса, и сами по себе они переживают и закрытие
окна, и снятие приложения в диспетчере задач, и даже работают без него после перезагрузки. Здесь это
специально не так.

- **Запуск.** Служба-менеджер зарегистрирована с типом запуска «Вручную». Приложение, не найдя пайпа,
  запускает её само: `sc.exe start AmnesiaWGHelper` (`src/main/tunnel/windows/serviceStart.ts`).
  Прав администратора это не требует — установщик дал интерактивным пользователям право запускать эту
  службу, но не останавливать и не перенастраивать её (`serviceSDDL` в `helper/service_windows.go`).
- **Остановка.** Приложение шлёт свой pid в каждом запросе, начиная с `hello`. Служба открывает описатель
  этого процесса и ждёт его завершения. Как только приложение исчезло — закрытием окна, падением или
  снятием процесса, — служба гасит туннель и останавливается сама, с кодом 0, чтобы не сработал
  перезапуск после сбоя. Если за минуту после старта ни одно приложение к ней не обратилось (её
  перезапустили после сбоя, запустили руками, установщик закрыли, не открыв приложение), она тоже
  останавливается. Решает это `helper/internal/lifetime`; наблюдение всегда за последним
  приславшим запрос процессом.

**На macOS то же самое, но сторожит не служба, а монитор.** `awg.sh up` получает `--app-pid` и
`--app-cmd` и кладёт их в root-овый файл состояния; фоновый монитор, который и так просыпается раз в
две секунды ради маршрутов, проверяет этот процесс и при его исчезновении сам делает `teardown`.
Сторожить должен кто-то уже с правами: умирающее приложение прав попросить не может. Номер процесса
проверяется вместе с именем — pid рано или поздно переиспользуется, и рвать туннель из-за
постороннего процесса было бы хуже исходной беды.

Разница с Windows: на macOS наблюдение не переводится на новый процесс, и перезапустившееся
приложение подхватить туннель не успеет — монитор погасит его в течение двух секунд. Это сознательно:
чтобы «переводить наблюдение», монитору нужен канал от неповышенного приложения, а любой такой канал —
это способ для чужого процесса продлить туннелю жизнь. Постоянных служб на macOS нет вовсе.

Следствие, общее для обеих систем: VPN без запущенного приложения не бывает. Обновление приложения
тоже рвёт подключение.

Код: `helper/` (Go), `src/main/tunnel/windowsHelperController.ts`, `src/main/tunnel/windows/`,
`resources/scripts/awg.sh` (`is_app`, `monitor_loop`).

## Сборка

Нужны Node и Go. Собирается и на macOS (helper — чистый Go, без cgo), и на Windows.

```
npm install
npm run build:helper     # resources/win/awg-helper.exe + wintun.dll (хеш закреплён и вшивается в хелпер)
npm run build:win        # dist/AmnesiaWG-<версия>-setup.exe (x64), один файл
```

Собранный файл — не мастер установки NSIS, а самораспаковщик (`portable`): он запускает приложение в режиме
установки, и оно само рисует экран и делает работу. Подробно — в [installer.md](installer.md).

С macOS собирается без wine. Подпись кода не настроена (ни `AmnesiaWG.exe`, ни `awg-helper.exe`, ни
установщик не подписаны) — до публичного релиза её надо добавить.

## Установка и удаление

Пользователь запускает скачанный файл, видит «Добро пожаловать!», выбирает быструю установку или папку и
нажимает «Установить»; UAC спрашивается один раз, в этот момент. Приложение ставится в папку с именем
AmnesiaWG (по умолчанию `C:\Program Files\AmnesiaWG`), а `awg-helper.exe` и `wintun.dll` — всегда в
`C:\Program Files\AmnesiaWG`: служба работает от SYSTEM, и её файл не должен быть доступен на запись
обычному пользователю. Приложение вне Program Files возможно, и его файлы пользователь заменить может, но
службу это не задевает — она запускает только свой файл.

Удаление — «Программы и компоненты» → `awg-helper.exe remove`: останавливает туннель и службы, стирает
`C:\ProgramData\AmnesiaWG`, папку приложения и `C:\Program Files\AmnesiaWG`, ключи реестра и ярлык.
Серверы пользователя (`%APPDATA%\AmnesiaWG`) остаются.

«Настройки → Приложение → Удалить AmnesiaWG» делает то же, но на виду. Диалог спрашивает «Сохранить
серверы и ключи?» («Да» выбрано заранее), и дальше экран удаления — экран установки наоборот: логотип
улетает из шапки в полное кольцо, кольцо сматывается на треть за шаг («Отключение и остановка службы» →
«Служба подключения» → «Файлы программы»), в конце гаснет. Устроено как установка: приложение запускает
`awg-helper remove --progress <файл>` через `runElevated` и следит за файлом прогресса
(`src/main/uninstall/`). С `--progress` хелпер не закрывает приложение и не показывает окон сообщений, а
пишет шаги; папку приложения он стирает, только когда приложение закроется («Завершить»). Ярлык, автозапуск
и — при ответе «Нет» — серверы, ключи и настройки удаляет само приложение, без прав: повышенный хелпер
может работать от другой учётной записи. Отказ в UAC возвращает в приложение как было; сбой останавливает
кольцо, показывает причину и кнопку «Вернуться в приложение», причина остаётся под «Удалением».

Экран без Windows: `AWG_UNINSTALL_SIMULATE=ok|fail|cancel npm run dev`.

## Вкладка «Приложение»

Есть на обеих системах (`src/main/appOptions.ts`,
`src/renderer/src/components/AppSettingsView.tsx`); раздел «Удаление» — только на Windows, на macOS
программу выбрасывают в Корзину и разбирать нечего.

**Автозапуск** — `app.setLoginItemSettings`. На Windows это запись в `HKCU\…\Run`, и путь берётся не
из `process.execPath`, а из `HKLM\SOFTWARE\AmnesiaWG\AppPath`: сразу после установки окно всё ещё
принадлежит временной копии из `%TEMP%`, и запись, указывающая туда, сломается при первой же уборке
временной папки. На macOS `path` и `args` не передаются вовсе — они windows-only, а элементом входа там
работает сам бандл через `SMAppService`. Переключатель показывает то, что система ответила после записи,
а не то, что просили.

**Автоподключение** — `autoConnect` в `settings.json` плюс `lastTunnelId`, который главный процесс пишет
сам при каждом `tunnel:connect`; страница его не трогает. Срабатывает после `manager.init()`, так что
туннель, поднятый прошлым сеансом, вторым подключением не перебивается.

Проверка: `sc query AmnesiaWGHelper` → `RUNNING` (установка сразу запускает службу; через минуту без
приложения она остановится сама); `resources\win\awg-helper.exe version`.

## Разработка на Windows

```
npm run build:helper
# консоль администратора, из корня проекта:
resources\win\awg-helper.exe install --dev
npm run dev
```

`--dev` разрешает службе работать из каталога проекта. Без него `install` отказывается: файл службы
должен лежать там, где его не заменит обычный пользователь (иначе это повышение привилегий до SYSTEM).
Убрать: `resources\win\awg-helper.exe uninstall`. После пересборки хелпера снова `install --dev`
(он останавливает службу и подхватывает новый файл).

Go-тесты (часть из них запускается только на Windows и сверяет настройки демона с macOS-путём):

```
cd helper
go test ./...
```

## Где смотреть, если что-то не так

| Что | Где |
|---|---|
| Журнал туннеля | вкладка «Логи»; файл `C:\ProgramData\AmnesiaWG\daemon.log` |
| Служба приложения | `sc query AmnesiaWGHelper`; если не стартует — «Просмотр событий» → Журналы Windows → Приложение, источник `AmnesiaWGHelper` |
| Служба туннеля (есть только пока подключено) | `sc query "AmneziaWGTunnel$AmnesiaWG"` |
| Адаптер и маршруты | `Get-NetAdapter`, `Get-NetRoute`, `Get-DnsClientServerAddress` |

## Что проверено на Windows

Прогнано вживую 20.09.2026: установка, подключение, отключение, перезапуск приложения при поднятом
туннеле, перезагрузка машины и аварийное завершение туннеля через диспетчер задач. Всё отработало.
Значит, работают служба, SCM, драйвер Wintun, маршруты, восстановление после перезапуска и — главное —
правила WFP не переживают смерть процесса туннеля и не оставляют машину без сети.

**Ещё не проверялось:** смена Wi-Fi и сон/пробуждение при поднятом туннеле, переключение между двумя
серверами одной кнопкой, **вкладка «Приложение»** целиком (автозапуск, автоподключение, удаление из неё)
и **весь новый установщик** (экран установки, `awg-helper setup`/`remove`, цель `portable`): проверенное
вживую 20.09.2026 было сделано NSIS-установщиком, которого больше нет. Порядок проверки — в конце
[installer.md](installer.md).

С macOS отдельно проверено, что конфиги всех поколений разбираются настоящим парсером форка и
настраивают демон так же, как macOS-путь (`helper/forkparse_windows_test.go`).

## Про два процесса awg-helper

Когда VPN подключён, в списке процессов их два, и оба там должны быть:

- `awg-helper.exe service` — служба-менеджер, работает, пока открыто приложение, даже с выключенным VPN;
- `awg-helper.exe tunnel` — служба туннеля, живёт только пока есть подключение.

Когда приложение закрыто, нет ни одного: оба исчезают сами в течение пары секунд после его завершения,
как бы оно ни завершилось (см. «Службы живут ровно столько, сколько приложение»).

## Чек-лист первого запуска

Порядок, в котором каждый шаг ломается по-своему:

1. Установщик отработал, `sc qc AmnesiaWGHelper` → `DEMAND_START`, в `sc sdshow AmnesiaWGHelper` есть
   `(A;;CCLCSWRPLOCRRC;;;IU)`. Приложение открывается **без UAC**, `sc query AmnesiaWGHelper` → `RUNNING`.
2. В «Логах» есть строка `amneziawg-go v3.1… — встроен в службу AmnesiaWG …` (значит, пайп работает).
3. Импорт `vpn://`-ссылки и подключение: появляется адаптер `AmnesiaWG`, карточка становится «Подключено»,
   растёт статистика. Первое подключение дольше остальных — ставится драйвер Wintun.
4. При полном туннеле и заданном в конфиге DNS: `nslookup example.com 8.8.8.8` должен **зависнуть** (DNS
   к любому серверу, кроме DNS туннеля, режет WFP), а `nslookup example.com` — отвечать. Внешний IP —
   адрес сервера.
5. «Отключить»: пропали адаптер, маршруты и служба `AmneziaWGTunnel$AmnesiaWG`, файл `AmnesiaWG.conf` удалён.
6. Закрыть приложение при поднятом туннеле — адаптер `AmnesiaWG` и обе службы пропадают сами в течение
   пары секунд (`sc query` → `STOPPED`, процессов `awg-helper` нет). То же при снятии процесса в
   диспетчере задач и при закрытии с выключенным VPN.
7. Завершить `awg-helper.exe` туннеля в диспетчере задач: приложение сообщает об остановке, интернет
   **не пропадает** (правила WFP умирают вместе с процессом), «Восстановить сеть» убирает остатки.
8. Перезагрузка с поднятым туннелем: сам он не поднимается, остатков нет; служба-менеджер не запущена,
   пока не открыто приложение.
   Снять `awg-helper.exe service` при открытом приложении: служба поднимается снова (восстановление после
   сбоя), приложение продолжает работать; после закрытия приложения она останавливается.
9. Смена Wi-Fi / сон и пробуждение при поднятом туннеле — трафик восстанавливается.
10. Переключение между двумя серверами одной кнопкой; обновление установкой поверх; удаление
    (после него нет ни службы, ни `C:\ProgramData\AmnesiaWG`).

Конфиги всех поколений протокола (`wireguard`, `legacy`, `2.0`, `3.0`, `3.1`) стоит подключить хотя бы
по одному, если есть серверы.

## Что важно знать

- Только **x64**. На Windows on ARM драйвер Wintun x64 не загрузится.
- Нет захвата пакетов («Диагностика» в настройках скрыта). Для разбора проблем — журнал и проверка связи.
- При полном туннеле WFP блокирует всё вне туннеля, пока жива служба туннеля: если сервер не отвечает,
  интернета нет (так устроен и официальный WireGuard). Отключение снимает правила.
- Управлять VPN может любой вошедший в систему пользователь этого компьютера (пайп открыт группе
  `INTERACTIVE`). Файл конфигурации с ключом им недоступен.
- Без подписи кода SmartScreen предупредит при установке.
- Ссылки с параметрами AmneziaWG, которых не знает служба, отклоняются сразу, с понятным текстом.
