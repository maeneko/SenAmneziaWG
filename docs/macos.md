# SenAWG для macOS: служба вместо пароля на каждое подключение

**Статус: реализовано, собирается и проходит тесты, но ни разу не запускалось от root.** Проверено:
`go vet` под все платформы, Go- и TS-тесты, сборка DMG, запуск службы через launchd по подключению к
сокету (в домене пользователя, `gui/<uid>`, без root). Не проверены установка в системный домен и
подключение туннеля через службу — это первый пункт чек-листа ниже.

Раньше каждое подключение, отключение и «Восстановить сеть» запускали `awg.sh` через
`osascript … with administrator privileges`, то есть с паролем администратора каждый раз. Теперь
`awg.sh` запускает root-служба launchd, а пароль спрашивается один раз — чтобы её поставить.

```
SenAWG (обычные права)
   │  JSON по строке — тот же протокол, что на Windows и Linux (helper/internal/proto)
   ▼  /var/run/ru.senawg.helper.sock (0666; отвечает только root и владельцу /dev/console)
launchd ── открывает сокет сам и запускает службу при первом подключении (socket activation)
   ▼
awg-helper service (root)       /Library/PrivilegedHelperTools/ru.senawg.helper/
   │  проверяет запрос; uid и pid отправителя — от ядра (LOCAL_PEERCRED/LOCAL_PEERPID)
   ▼
awg.sh up/down (root-копия)     маршруты, DNS, монитор — тот же скрипт, что и раньше
   ▼
amneziawg-go (root-копия)
```

## Что идёт через службу, а что нет

Через службу — только то, что требует root: `up`, `down`, `cleanup`. Остальное приложение читает само,
как и раньше: `/var/db/senawg/state.env` доступен всем на чтение, а UAPI-сокет демона `awg.sh` отдаёт
пользователю, который поднял туннель. Поэтому запуск приложения никогда ничего не спрашивает — даже
если службы ещё нет.

| Действие | Кто делает |
|---|---|
| подключение, отключение, «Восстановить сеть» | служба → `awg.sh` |
| найти работающий туннель при старте, статистика, монитор жив ли, захват пакетов | приложение само |
| журнал движка | `/var/db/senawg/daemon.log` (строки службы — с префиксом «служба:») |

## Установка, обновление, удаление

**Установка** — при первом подключении. Сокета нет → приложение запускает
`awg-helper install --from <Contents/Resources>` через тот же `osascript` с паролем
(`src/main/tunnel/macos/service.ts`), затем продолжает подключение. Установка
(`helper/install_darwin.go`):

1. копирует `awg-helper`, `amneziawg-go`, `awg.sh` в `ru.senawg.helper.next` рядом с целевой папкой;
2. `launchctl bootout` старой службы, папки меняются местами переименованием (`internal/setup/swap.go`);
3. проверяет, что всё на пути к файлам службы принадлежит root и не доступно на запись другим —
   ту же проверку служба делает при каждом запуске и без неё ничего не запускает;
4. пишет `/Library/LaunchDaemons/ru.senawg.helper.plist`, `launchctl enable` + `bootstrap`, ждёт сокет;
5. при сбое на шагах 3–4 возвращает всё как было (прежнюю службу и её plist, или ничего).

Туннель установка не трогает: он принадлежит процессам `awg.sh` (свой сеанс, `Setsid`, плюс
`AbandonProcessGroup` в plist), а не службе.

**Обновление.** Служба отвечает на `hello` своим build id — SHA-256 от хешей трёх её файлов
(`helper/macinstall.go: buildID`, тот же расчёт в `serviceBuildId`). Перед каждым подключением
приложение сравнивает его с хешем своих `Resources`; если отличается — переустанавливает службу, один
раз спросив пароль. Обновление, в котором служба не менялась, пароля не спрашивает.

**Удаление** — «Настройки → Приложение → Служба SenAWG → Удалить службу» (только при выключенном VPN)
или вручную: `sudo /Library/PrivilegedHelperTools/ru.senawg.helper/awg-helper uninstall`. Убирает
службу из launchd, plist, папку службы, сокет, лог; если туннель поднят — сначала `awg.sh down`;
`/var/db/senawg` удаляется, только если после этого не осталось `state.env`.

Если просто перетащить SenAWG в Корзину, служба останется. Вреда от неё нет — без приложения её никто
не позовёт, — но место она занимает; поэтому в настройках есть кнопка, и о ней там же сказано.

## Безопасность

- Служба не запускает ничего из бандла приложения: `/Applications/SenAWG.app` доступен на запись без
  root, и тогда подмена `awg.sh` дала бы root любому процессу пользователя. Только свои копии.
- Какой демон запускать, для какого uid и за каким приложением следить — служба решает сама
  (`helper/awgsh.go: awgShUpArgs`), из запроса это не берётся. Все адреса разбираются заново и
  собираются из разобранных значений; в `awg.sh` не попадает ничего, кроме адресов.
- Отвечает служба только root и владельцу `/dev/console` — пользователю за экраном. Другая учётная
  запись по ssh или в фоне быстрого переключения пользователей туннель не включит и не выключит.
- Ключ идёт в `awg.sh` файлом `0600` в `/var/db/senawg` (как и раньше — не в argv).

## Сборка и разработка

```
npm run build:awg            # resources/bin/amneziawg-go (universal)
npm run build:helper:mac     # resources/bin/awg-helper (universal, cgo — только на macOS)
npm run build:mac            # всё вместе + DMG
```

`npm run dev` по-прежнему спрашивает пароль на каждое подключение (`MacosScriptController`). Чтобы
разрабатывать через службу: `SENAWG_MAC_SERVICE=1 npm run dev` — служба поставится из `resources/` проекта.

Проверить службу, не трогая сеть (`hello` и `status` ничего не меняют):

```
echo '{"v":1,"op":"hello"}'  | nc -U /var/run/ru.senawg.helper.sock
echo '{"v":1,"op":"status"}' | nc -U /var/run/ru.senawg.helper.sock
sudo launchctl print system/ru.senawg.helper    # состояние, число запусков, код последнего выхода
cat /var/log/ru.senawg.helper.log               # то, что служба не смогла написать в daemon.log
```

## Чек-лист первого запуска на настоящей машине

Лучше на Mac, где VPN можно ненадолго потерять: переход с прежней версии опускает туннель, поднятый
по-старому, когда старая версия закрывается.

- [ ] Первое подключение: один запрос пароля с текстом про установку службы; туннель поднимается.
- [ ] macOS показывает уведомление «Добавлен фоновый объект»; в «Объектах входа» служба видна — под
      именем SenAWG или отдельно (с ad-hoc подписью `AssociatedBundleIdentifiers` может не сработать).
- [ ] Отключение и повторное подключение — без пароля. Смена сервера — без пароля.
- [ ] `nc -U … hello` отвечает с `build`; «Настройки → Приложение» показывает «Установлена, версия …».
- [ ] Закрыть приложение с поднятым туннелем → туннель опускается (монитор `awg.sh`); служба завершается
      сама (`launchctl print` → `state = not running`).
- [ ] `kill -9` приложения → то же.
- [ ] Сменить сеть (Wi-Fi ↔ другой Wi-Fi) при поднятом туннеле → маршрут до сервера перестраивается.
- [ ] «Диагностика подключения» включена → захват пакетов появляется в журнале.
- [ ] Обновление без изменений службы → пароль не спрашивается. С изменённым `awg.sh` → спрашивается
      один раз при следующем подключении; туннель, поднятый до обновления, не рвётся от переустановки.
- [ ] Выключить службу в «Объектах входа» → подключение показывает понятную ошибку про «Объекты входа».
- [ ] Отменить запрос пароля при установке → «подключение отменено», без ошибки.
- [ ] «Удалить службу» при включённом VPN → «Сначала отключите VPN»; при выключенном — пароль, раздел
      показывает «Не установлена»; следующее подключение ставит её снова.
- [ ] Второй пользователь (быстрое переключение) → служба ему отказывает с понятным текстом.

## Файлы

| Где | Что |
|---|---|
| `helper/main_darwin.go` | команды `service`, `install`, `uninstall`, `version` |
| `helper/tunnel_darwin.go` | движок: `awg.sh` от root, `status`/`stats` по `state.env` и UAPI, проверка прав на файлы |
| `helper/socket_darwin.go`, `launchd_darwin.go` | сокет от launchd (cgo), отправитель запроса, кому отвечать |
| `helper/install_darwin.go`, `macinstall.go` | установка и удаление, plist, build id |
| `helper/awgsh.go` | аргументы `awg.sh` из запроса, разбор `state.env` и вывода скрипта |
| `src/main/tunnel/macosServiceController.ts` | контроллер приложения |
| `src/main/tunnel/macos/service.ts` | установка по первому подключению, build id, состояние и удаление службы |
| `/Library/PrivilegedHelperTools/ru.senawg.helper/` | установленная служба (root:wheel, 0755) |
| `/Library/LaunchDaemons/ru.senawg.helper.plist` | задание launchd |
| `/var/run/ru.senawg.helper.sock` | сокет службы |
| `/var/db/senawg/` | состояние, журнал и захваты `awg.sh` |
